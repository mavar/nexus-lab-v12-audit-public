Сначала этот импорт не прошёл, затем путь был найден и проверка повторена с исправленной обёрткой. Ошибка окружения не считается ошибкой проекта.

Потребление токенов/списания отдельным доступным счётчиком не измерены; оценка затрат качественная: локальные скрипты и ограниченные мини-опыты, без платных внешних моделей и нового полного поиска.

## Команды

В PowerShell, после перехода в отдельную копию:

```powershell
& "$env:LOCALAPPDATA/NEXUS_Runtime/cuda126_py312/Scripts/python.exe" -X utf8 START.py --smoke --cpu
```

Далее из папки отчёта:

```powershell
& "$env:LOCALAPPDATA/NEXUS_Runtime/cuda126_py312/Scripts/python.exe" -X utf8 ./audit_checks.py
& "$env:LOCALAPPDATA/NEXUS_Runtime/cuda126_py312/Scripts/python.exe" -X utf8 ./extra_checks.py
```

audit_checks вызывает pytest.main для `tests/test_v12.py`, отключив автоматическую загрузку сторонних plugins. Эквивалент при установленном pytest в нужном окружении: `python -m pytest -q tests/test_v12.py`. Не запускать произвольный системный Python без torch и считать это провалом кода.

Для нового повторения подготовка копии автоматизирована:

```powershell
python ./run_audit.py
```

Ожидается 3–8 минут при текущей нагрузке; жёсткие лимиты этапов 180/300/120/120 секунд. Новые результаты складываются в evidence/reruns/<время>, исходные доказательства этого аудита сохраняются. После повторения нужно читать JSON наблюдений: воспроизведённые ошибки здесь сознательно не превращены в падения скрипта. Наличие completed=true означает выполнение проверок, не отсутствие ошибок программы.

## CPU и GTX 1070 — одна и та же функция V12

По 3 повторения после короткого прогрева; 24 эпохи, один full LONG геном, реальные prepared. Полное время eval_gene измерено perf_counter, GPU синхронизирована на границах. Пик ниже — torch allocated этого процесса, не общая занятость карты. Другой процесс и графический рабочий стол используют карту отдельно.

Малые сети и частые небольшие batch требуют измерения накладных расходов. CUDA действительно работает; старые V10 бенчмарки в вывод не подставлялись.

## Масштаб

100k ID: encode+decode 0.184s, encoded 184484 bytes. 1M ID: 1.318s, encoded 1844064 bytes, decoded int64 8MB. Это проверка хранения ID, а не обучения на миллионе строк. 1M×26 float32 только X около104MB; выбор/нормализация/тензоры добавят несколько копий. Опаснее бессрочный кэш и повторение больших геномов: 100k записей по1.84MB ≈184GB до curves/JSON overhead. Оценка, не проведённый дисковый стресс на184GB.

## Что не запускалось и почему

- Новый полный 18000-слотовый поиск: не нужен для аудита, уже работал исходный процесс; задача требует начинать с ограниченных опытов.
- Полноценное обучение на 1M и журнал100k полных геномов: проверены обучение на100k и кодирование до1M, стоимость остального оценена, тяжёлый стресс перенесён в отдельный ограниченный опыт после исправления корректности.
- Полное восстановление raw→prepared и официальное покрытие сессий: исходные CSV/паспорт времени не переданы.
- Полный null-эксперимент на20+ seeds, настоящая новая финальная неделя, широкие/глубокие/ветвящиеся сети: предложены, но не выданы за выполненные.
- DQN, ансамбли, bandit и старые legacy: не требуются для проверки текущего действующего кода.
- Торговые заявки, комиссии/прибыль, live рынок: не запускались; цель текущего V12 — распознавание меток Finam SBRF.

Полное обучение на1M и многопоколенный поиск на100k не выполнялись.

Отдельно выполнен cProfile реального 1m-кандидата на CPU/CUDA; команда `python profile_candidate.py` в проверенном окружении. Wall-clock под профилировщиком4.858/4.684s; его накладные расходы отличаются от обычного бенчмарка. Детали в evidence/profile.txt.

Обёртка run_audit.py синтаксически проверена; перечисленные этапы фактически запускались отдельно. Саму обёртку целиком второй раз не запускали, чтобы не повторять уже выполненные вычисления.
