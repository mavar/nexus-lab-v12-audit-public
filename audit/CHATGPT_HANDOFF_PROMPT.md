## Задача

Нужно искать группы похожих полезных учебных примеров, на которых нейросеть лучше узнаёт новые рыночные ситуации. Прибыль пробной модели сама по себе не доказывает качество группы. Разрешены старые, ранее неотмеченные и ранние примеры, но происхождение и смысл новой метки нужно сохранять. LONG и SHORT проверяй отдельно.

Начни с маленьких групп от 10 независимых примеров, наращивай их, сохраняй коллекцию. Одновременно исследуй маленькие, средние и большие наборы. Предложи собственный генетический поиск, объясни гены, мутации, сохранение разнообразия и выбор победителей. Обучай новую сеть для каждого нового смыслового набора. Не подменяй эту задачу подбором случайных правил входа.

## Данные

1. Finam/SBRF: v12_source/prepared, пять размеров свечей, июль–сентябрь 2026. Исходные Finam CSV и точный паспорт времени/контракта не переданы.
2. MEXC спот: data/crypto_1m, пять CSV для SOLUSDT, BTCUSDT, ETHUSDT, XRPUSDT, DOGEUSDT. Календарь 3–30 июня 2026, UTC, по 40320 минутных строк с отмеченными пустотами. Это 25 наблюдавшихся, но не 25 полных суток.
3. Готовые 25 таблиц: data/prepared_crypto. Те же 26 названий признаков, метки, источник и split.
4. Короткие примеры: data/crypto_1m/*_example.json.

Пропуски не заполнять придуманными ценами. Уникальность всех исходных сделок не доказана: одинаково выглядящие строки сохранены и посчитаны. Объём — сумма записанных наблюдений. Минутный OHLCV не позволяет восстановить точный профиль объёма по ценам.

Пример чтения:

```python
import pandas as pd
from tools.prepare_crypto import FEATURES
x = pd.read_csv('data/prepared_crypto/SOLUSDT_1m_research.csv.gz')
train = x[x.split == 'train']
select = x[x.split == 'select']
check = x[x.split == 'check']
X = train[FEATURES]
y = train.long_label
```

Метка: изменение close через 60 минут не менее 0.25%. Это движение цены до расходов, не чистая прибыль. Не передавай future_* и целевую метку во вход модели. Проверяй, что расчёт признаков использует только уже полученную историю. Разделение по времени и защитный промежуток должны учитывать полный горизонт ответа.

## Код и ограничения

Исходный V12: v12_source/research/evolve_datasets.py. В нём зашиты имя SBRF, календарь и граница SELECT 2026-08-24. Сначала сделай их параметрами: простой перенос июньской крипты в файл SBRF даёт неверный расчёт окна. Не переименовывай инструмент и не подменяй даты.

Демонстрация формата и обучения на шести инструментах: tools/smoke_multi_market.py. Это технический пример фиксированной сети, а не готовый полный генетический поиск. Полный разбор старых результатов — audit/COMPLETED_RUN_REVIEW.md.

Подтверди ошибку старых оценок настоящим запуском tools/verify_cache_definitively.py. Исходный опыт показал: после изменения признака прежняя папка вернула старый результат с нулём обучений; новая папка выполнила 15 обучений и дала другую оценку. Исправление должно исключать и смешение старых оценок кандидатов с новыми конечными проверками.

## Честная проверка

Обязательные контроли: вся исходная база; случайные группы того же размера, происхождения и весов; простой отбор сильных движений; перемешанные метки. Зафиксируй отрицательные примеры, нормализацию, устройство и случайные старты. Равные эпохи и равное число обновлений сети проверь отдельно, не называй их одинаковым бюджетом.

Соседние свечи одного движения не считать независимыми доказательствами. Оценивай по нескольким поздним временным блокам и разным стартам сети. Не подбирай параметры по CHECK. Опубликованные CHECK уже просмотрены: после изменения метода нужна новая нетронутая финальная история.

Сохраняй точные ID примеров, источники меток, родителей, изменения состава, настройки сети, seeds, хэши данных/кода/окружения, число обновлений, кривые обучения, ошибки, время и память.

Верни исполняемый код с командой запуска, JSON/CSV результатов, понятную таблицу найденных групп и причины неудач. Отдели выполненные проверки от предложений. Если интернет или запуск кода недоступны, скажи это прямо и попроси приложить открытый ZIP. Не выдумывай результаты.
