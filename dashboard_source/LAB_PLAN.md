# План пробного теста

Стабильная версия графика v1.0.0 — коммит `745ff4bac39e015c7eb4cc49642ac80119ff1546`. Владелец выбрал все три правила. Исторические прогоны июня доступны в [локальной вкладке тестов](TEST_LAB_SETUP.md); будущей недели в API нет.

| № | Правило | Что держим в памяти |
|---|---|---|
| 1 | Движение за 10 секунд: вход при превышении порога известного изменения цены | Кольцо примерно из 11 секундных цен, вычитание или отношение |
| 2 | Пересечение быстрой и медленной сглаженных средних на уже известных ценах | Две средние и знак предыдущей разницы |
| 3 | Пробой максимума предыдущей минуты без текущей секунды | Минутное окно и очередь для максимума |

Для обкатки все три правила работают без модели. Секундная цена строится только по последней полученной к этой секунде котировке. После сквозной проверки можно использовать разметку для подбора порога или обучения, соблюдая те же временные границы.

1. Настройка — 14–20.06.2026 UTC, на имеющихся чистых отрезках. Входы и признаки используют только уже полученные события. Метки могут смотреть вперёд только внутри обучающего отрезка; исключить пересечения временных границ. Проверить комиссии, спред, задержку и отсутствие входов в разрывах. Порог/другие параметры подбирать только на этой неделе. Перед большим перебором стартовать с небольшого списка; сохранять все попытки и отдавать предпочтение устойчивым соседним настройкам.
2. До 23.11.2026 00:00 UTC подтвердить сбор SOLUSDT `book_ticker` и покрытие нужных полей. Зафиксировать список проверяемых комбинаций, код, параметры, исходники, комиссии и правила подсчёта. Выход задним числом годится для меток; в тесте решения о выходе должны опираться на заранее заданные цель, стоп и время. Устранить расхождение: текущий Python Harness задерживает исполнение на тики, а эта разметка — на 300 мс. На нерегулярных котировках это не одно и то же. Не смешивать единицы результатов условного шорта разных движков: для первого сквозного прогона рекомендуем лонг.
3. Будущий контроль: `[2026-11-23T00:00:00Z, 2026-11-30T00:00:00Z)`, с понедельника по воскресенье. До окончания периода не смотреть исходы и не подбирать по нему настройки. Писать журнал доступа; проверку пригодности котировок отделять от расчёта прибыльности. Если запись не состоялась или независимость нарушена, перенести контроль на следующую будущую неделю до просмотра её исходов.
4. После закрытия периода — один заранее объявленный сравнительный прогон зафиксированных вариантов через Harness (сначала обязательная самопроверка). У каждой строки: ID, параметры, число сделок, чистый итог, просадка и доля плюсовых на обеих неделях, плюс непригодные интервалы. Отсутствие достаточного числа сделок не объявлять успехом. Победителя, заново выбранного по проверочной неделе, оценивать на ещё одном неиспользованном периоде. Для сотен вариантов сохранять число попыток, проверять устойчивость и учитывать множественный перебор.

Ноябрьская запись на момент подготовки не подтверждена. Дата является целевым независимым интервалом, а не готовым набором данных.
