## Недельный дашборд

1. Перенести шапку в колонки 20 / 30 / 50%, убрать кнопку «две минуты», выделить основную кнопку и итог, применять точные значения цели, срока и падения из результата.
2. Показать все рассчитанные сочетания в рейтинге, сортировать по итоговой сумме, фильтровать диапазоны цели, срока, падения и итога; применять выбранную строку.
3. Собрать семь календарных дней 14–20 июня UTC с картой разрывов. Проверить графики и поиск по часу, дню, произвольному интервалу и неделе. Неделя и пользовательский диапазон на нескольких датах: деньги переходят между днями, позиции через полночь отключены. Разрывы не восполняются.
4. Добавить покупки, условные шорты и общий режим с одной позицией на оба направления. Формулы и ограничения указать рядом с расчётом. Проверить автоматический подбор в каждом режиме.
5. Проверить отклик графиков, точное применение параметров, расчёт, фильтры и данные. Передать локальный HTML. Подготовить отдельный Git-репозиторий только кода; сверить приватность и восстановление свежим клоном.

Полный прогон с минимум 20 закрытыми сделками имеет приоритет, затем итоговый баланс, просадка и число сделок. Если никто не прошёл отбор, показать пробный итог без переноса настроек и без фиксации.

## Направления обучения

- «Лонг» и «Шорт» размечают, обучают и проверяют свою сторону. «Оба» обучает две модели на раздельных метках. У них один порог входа и один набор торговых параметров для каждого сочетания. В одну секунду выбирается более высокая оценка, равная оценка отдаёт приоритет лонгу. Общий баланс и максимум одна позиция.
- Шорт исполняется как условная продажа по bid и обратная покупка по ask, с комиссией и задержкой на каждой стороне. Плата за заём и ликвидации не моделируются.
- Подбор проверяет полное произведение чисел из интерфейса. При недостатке учебных меток настройки учитываются в числе пропусков. Входы и границы разрывов вычисляются один раз на день. Оценки моделей и сигналы для каждого порога используются повторно для разных значений стопа.

Выполнено и проверено 17.11.2026. В браузере дерево проверило по 96 из 96 сочетаний отдельно для лонга, шорта и режима «Оба». Прежний и ускоренный лонг совпали во всех 96 строках рейтинга и в полном результате, 17,13 → 5,75 с при замере в одном процессе после прогрева. Harness 7/7, Python 11/11, движок 504/504.

## Объём и расходы

- Окно объёма участвует в полном переборе. Стартовый набор сравнивает 0, 60 и 120 секунд. Ноль отключает объём. Используются только сделки, полученные до решения. Цена разбита по шагу 0,05 USDT. Признаки включают число и размер сделок, изменение частоты, уровень с наибольшим объёмом, движение к нему, сильные уровни выше и ниже. После пауз потока свыше двух минут ждём заполнения окна.
- Сравнение настроек остаётся на 18–20 июня, после обучения на 14–17 июня. Дополнительный вес редких удачных входов пробовали отдельно. Дерево и логистическая модель стали открывать больше убыточных сделок, поэтому повышенные веса убраны.
- В разметке и исполнении учитываются разница цен покупки и продажи, комиссия за каждое исполнение и заданное ухудшение цены. Начальная комиссия 0,05% соответствует стандартной ставке MEXC для рыночного спотового ордера. Тариф конкретного счёта можно ввести в форме. Обучение на шортах требует котировки фьючерса SOL_USDT, сделки, комиссии и выплаты за удержание. При подключённой спотовой базе запуск шортов отключён. [Спотовая комиссия MEXC](https://www.mexc.com/support/article/beginner-s-guide-to-spot-trading-faq-332253318490269696), [выплаты по фьючерсу](https://www.mexc.com/support/article/mexc-futures-funding-rate-305432020820705280).

Проверка на июне: в каждой модели 288 сочетаний без пропусков. Окно 120 с дало лучший итог для всех трёх. Дерево 98,61 USDT вместо 97,52 без объёма, логистическая модель 92,62 вместо 92,40, Байес 22,73 вместо 20,58. Старт 100, комиссия 0,05% в обе стороны, дополнительное ухудшение цены 0%. Будущая неделя не открывалась.

Открытый API MEXC вернул для SOLUSDT спотовую комиссию 0,05% и минимум 1 USDT для рыночного ордера. История выплат SOL_USDT за 14–20 июня содержит 21 запись. Для воспроизведения сделок с задержкой 300 мс требуется отдельный архив котировок фьючерса и его сделок. Публичный API MEXC даёт последние изменения стакана и до 100 последних сделок.
