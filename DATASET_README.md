# Реальные данные для проверки алгоритмов

В наборе два рынка, которые нельзя смешивать под одним именем:

- `v12_source/prepared/SBRF_*m_research.csv.gz`: предоставленные подготовленные данные Finam/SBRF,июль–сентябрь2026. Исходные raw Finam и точный паспорт контракта/таймзоны не были переданы; это ограничение сохранено.
- `data/crypto_1m/*_1m.csv`: MEXC **спот**,SOLUSDT/BTCUSDT/ETHUSDT/XRPUSDT/DOGEUSDT,3–30июня2026,UTC. Это сделки рынка, а не сделки владельца. Никаких торговых ключей.

## Объём и качество

28 календарных суток представлены непрерывной минутной сеткой,40320 строк на пару. Исходные наблюдения есть в25датах, но дни частичные. Не говорить «25полных дней без пропусков». Пропуски оставлены пустыми. Цена не переносится вперёд. Статистика ниже не доказывает полноту потока биржи — только наличие записанных наблюдений.

В исходнике нет уникального биржевогоID сделки. Обнаружены одинаково выглядящие записи (по времени/цене/количеству); они сохранены и посчитаны в identical_looking_trade_rows, поскольку одинаковые исполнения могут быть настоящими. **Уникальность всех сделок не доказана; объём — сумма записанных строк, возможная чувствительность к повторениям требует проверки.** Не использовать его как безусловно точный биржевой оборот.

`price_bar_ok`: есть положительные конечные цены/количества, без недопустимых trade-строк в минуте. `quote_bar_ok`: котировки не перепутаны, не содержат недопустимых значений, последняя не старше2секунд к закрытию минуты, максимальная пауза котировок не больше2секунд. Более строгий флаг не удаляет данные из исходного CSV.

## Схема

- `dt`: UTC-время, когда вся минута завершилась и значения уже были доступны.
- `bar_start_utc`: начало полуоткрытой минуты [start,end). Все события сгруппированы по **моменту получения recv_ts_ms**, не по будущему биржевому времени.
- `open/high/low/close`: первая/максимальная/минимальная/последняя записанная цена сделки в минуте; при одинаковом recv_ts сохраняется порядок строк источника.
- `volume`: количество базовой валюты в записанных сделках, `quote_volume`: сумма price×quantity вUSDT. `trade_count`: число допустимых строк.
- `best_bid/best_ask,bid_qty/ask_qty`: последняя допустимая котировка минуты. Размеры очереди **не являются торговым объёмом**.
- `spread_bps`: спред в сотых долях процента.100bps=1%.
- `last_quote_ts_ms`, `last_quote_age_ms`, `max_quote_gap_ms`, `quote_rows`, `invalid_quote_rows`, `invalid_trade_rows`: наблюдаемое качество.

По минутномуOHLCV нельзя восстановить точный объём по каждой цене и порядок событий внутри свечи. Признаки close_volume_gravity/volume_pivot_distance — лишь приближения по свечам. Для подробного горизонтального объёма и исполнения использовать исходные сделки/котировки, а не выдавать эти приближения за точный профиль.

## Время обучения и метки

Пример протокола: TRAIN до21.06,SELECT21–25.06,CHECK26–30.06. CHECK — исторический период, а не будущее от текущей даты; после знакомства с ним новый метод нуждается в новой независимой финальной проверке.

`tools/prepare_crypto.py` создаёт26признаков и long_label/short_label: изменение close через60минут не менее0.25%. Это **изменение цены до расходов, не чистая прибыль**. Две стороны хранятся отдельно. Признаки используют только уже завершённые бары, нормализация не включена в таблицу и должна обучаться только наTRAIN.

Сохраняется дневная политика примераSBRF: не переносить целевое окно черезUTC-полночь; для крипты это условность протокола, не закрытие биржи. Не хватает полного будущего окна без пропусков — строка не размечается. Требуются26последовательных наблюдавшихся баров перед входом. Ранние альтернативныеfuture_15m/30m/60m сохраняются как другие гипотезы; их конечное окно не пересекает split.

Готовые25таблиц: `data/prepared_crypto/{SYMBOL}_{1,5,10,15,30}m_research.csv.gz`. В каждом файле те же26имен признаков, что уV12/SBRF, плюс стабильныйsource_row_id,источник,splits и метки. В30m мало примеров из-за длительного дневного прогрева; для технической проверки начинайте с1m, не заявляйте результат малого30m как устойчивый сигнал.

**Важное ограничение исходногоV12:** нельзя просто положить криптовалюту в файлSBRF и запуститьSTART.py. Reader,calendar splits и score cut2026-08-24 зашиты в код. Это подтверждённая задача016. Адаптер делает данные удобными, но не исправляет сам генетический движок. `tools/smoke_multi_market.py` — отдельная фиксированная нейросеть для проверки формата, не готовый полныйGA.
